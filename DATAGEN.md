# Iron Spells Genesis Datagen

This project keeps almost all `data/iron_spells_genesis` files generated from Java.

Keep these data folders handwritten for now:

- `worldgen/**`
- `dimension/**`
- `dimension_type/**`
- `forge/biome_modifier/**`
- `loot_tables/**`
- `patchouli_books/**`

Do not edit JSON under `src/generated/resources` directly. Change the Java datagen source, then run `runData`.

## Entry Points

Main event entry:

```text
src/main/java/miku/united_as_one/genesis/data/datagen/DataGenerators.java
```

Registrate entry:

```text
src/main/java/miku/united_as_one/genesis/data/datagen/ModRegistrateData.java
```

`DataGenerators` registers standard providers:

- `ModDatapackEntriesProvider`
- `ModDamageTypeTagProvider`
- `ModMobEffectTagProvider`
- `ModCuriosDataProvider`
- `ModBlockStateProvider`

`ModRegistrateData` registers Registrate providers:

- recipes
- item tags

## Registry Data

Registry-backed datapack data is generated by one provider only:

```text
src/main/java/miku/united_as_one/genesis/data/datagen/provider/ModDatapackEntriesProvider.java
```

Do not add another `DatapackBuiltinEntriesProvider` for this mod unless it has a unique provider name. Minecraft's default name is `Registries`, and two providers with that name will crash datagen with `Duplicate provider: Registries`.

Current registry bootstrap sources:

- `DamageTypes.bootstrap`
- `ModUpgradeOrbTypeProvider.bootstrap`

Upgrade orb types use the helper builder in:

```text
src/main/java/miku/united_as_one/genesis/data/datagen/provider/ModUpgradeOrbTypeProvider.java
```

Add new orb types with:

```java
type(UpgradeOrbTypes.EXAMPLE)
        .attribute(SpellAttributesRegistry.EXAMPLE)
        .container(ItemRegistry.EXAMPLE_ORB)
        .save(context);
```

## Recipes

Recipes are centralized in:

```text
src/main/java/miku/united_as_one/genesis/data/datagen/provider/recipe/RecipeGen.java
```

Use builder style:

- vanilla crafting: `ShapedRecipeBuilder` / `ShapelessRecipeBuilder`
- smithing: `SmithingTransformRecipeBuilder`
- arcane workbench: `ArcaneWorkbenchRecipeBuilder`
- alchemist cauldron brew: `AlchemistCauldronBrewRecipeBuilder`

Do not add `StaticRecipe` or raw JSON text blocks.

## Curios

Curios entity and slot data is generated by the local builder provider:

```text
src/main/java/miku/united_as_one/genesis/data/datagen/provider/ModCuriosDataProvider.java
```

Use `entities(...)` and `slot(...)`; do not write Curios JSON by hand inside datagen. The provider writes the normal Curios JSON shape directly so datagen does not depend on Curios' runtime data-provider mixin.

## Run

```powershell
.\gradlew.bat runData --no-daemon --console=plain
```

Common checks:

```powershell
.\gradlew.bat compileJava --no-daemon --console=plain
.\gradlew.bat processResources --no-daemon --console=plain
```

The `data` run sets `ias.skipDisableScanning=true` in `build.gradle` to avoid the IAS remote-check thread during datagen. `DataGenerators` also registers a final exit guard so runtime-only mod threads cannot keep the datagen JVM alive after all providers and the hash cache finish.

If a previous broken `runData` already left a lock behind, inspect and clean only the data-run Java processes:

```powershell
Get-CimInstance Win32_Process -Filter "name = 'java.exe'" |
    Where-Object { $_.CommandLine -like '*runData*' -or $_.CommandLine -like '*dataRun*' } |
    Select-Object ProcessId, CommandLine
```
